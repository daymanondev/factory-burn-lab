# ADR 0003 — Genuine `paseo-factory` core integration (`createFactory`, `runGate`, `loadLanes`, `runLaneCli`, `diffBetween`, `WATCH_QUESTIONS`, `landTaskWorktree`) and shared `Project` registry

- **Status:** Accepted — 2026-10-17 (ratified by Andrew over a two-round `/grill-with-docs` session; words "vì burn lab được coi là 1 plugin của factory, nên chỉ khi có factory chúng ta mới cài đặt được burn lab. Còn lại theo khuyến nghị của bạn" and "toàn bộ theo bạn khuyến nghị")
- **Amends:** ADR 0001 §1–§4 (replaces `factory-burn-lab`'s standalone re-implementations of project resolution, lane invocation, gate execution, worktree diffing, and council review with direct consumption of `paseo-factory`'s pure-Node verification core)
- **Context:** In `v0.0.1`–`v0.0.2`, `factory-burn-lab` only read `<paseoHome>/factory/projects/` and `lanes.json` as raw JSON files and re-implemented miniature versions of `resolveProjectIdentity`, `parseSupervisorLane`, `defaultSupervisorRunner`, `defaultGateRunner`, `prepareIsolatedWorktree`, and `runCouncilCrossCheck` in `src/burn-engine.ts`. Because of this duplication, `factory-burn-lab` missed `paseo-factory`'s process-group `runGate` (`NODE_TEST_CONTEXT` stripping, `-pid` SIGKILL, `artifact` check), clean-room `PI_CODING_AGENT_DIR` isolation (`runLaneCli` + `provisionPiAgentHome`), `MEMORY_FILES` fencing (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`), real `git diff` verification (`checkCleanAt`, `changedFiles`, `changesOutsideScope`, `diffBetween`), `Attempt` rework loops, `WATCH_QUESTIONS` (`test-weakened`, `secret-leak`, `scope-creep`, `destructive-writes`), and safe worktree landing (`landTaskWorktree`). Meanwhile, under `paseo-factory` ADR 0012, `factory-burn-lab` is an official `Companion plugin` installed from and alongside `paseo-factory`.

## Decision

1. **Vendored `paseo-factory` Core Sync (`src/factory-core/` → `plugin/server/core/factory-core/`).**
   - `scripts/sync-plugin-core.mjs` syncs `paseo-factory`'s pure-Node modules (`../research-slp/src/*.ts`) into `src/factory-core/` and mirrors `src/` (including `factory-core/`) into `plugin/server/core/`.
   - This satisfies Paseo's plugin compiler boundary (`scripts/check-bundle.mjs` builds `plugin/index.server.ts` from git-tracked files inside `plugin/` alone) while guaranteeing that `factory-burn-lab` executes the exact `paseo-factory` verification primitives (`createFactory`, `runGate`, `loadLanes`, `runLaneCli`, `resolveProject`, `projectStateDir`, `diffBetween`, `changedFiles`, `changesOutsideScope`, `landTaskWorktree`, `MEMORY_FILES`, `WATCH_QUESTIONS`, `parseEyeAnswer`).

2. **Unified `Project` Registry & `Lane config` with `paseo-factory` (`<paseoHome>/plugin-state/paseo-factory/`).**
   - Because `factory-burn-lab` is only installed when `paseo-factory` is present, `factory-burn-lab` reads and writes `Project` registrations directly in `paseo-factory`'s `<factoryStateDir>/projects/<slug>/project.json` (`<paseoHome>/plugin-state/paseo-factory/projects/<slug>/project.json`, with fallback to `<paseoHome>/factory/projects/`) and resolves `lanes.supervisor` via `loadLanes(factoryStateDir, slug)`.
   - Adding or initializing a repository on the `Burn Lab` surface (`burn.project.add`) or ensuring a `Supervisor` seat (`burn.supervisor.open`) updates `paseo-factory`'s project registry so both surfaces (`Factory` and `Burn Lab`) always display the exact same `Project` list and `Supervisor` seat.
   - Strong `Supervisor` framing and synthesis passes invoke `runLaneCli` from `paseo-factory` core (preserving `:thinking` / `--effort` flags and `provisionPiAgentHome` clean-room `PI_CODING_AGENT_DIR` isolation).

3. **Run-Scoped `createFactory` Verification Line & Self-Repair Rework Loop (`maxAttempts = 2`, up to `MAX_ATTEMPTS = 3`).**
   - For every code-producing `Burn run` (`Proto arena`, `Night shift`, `Self-evolve`, and the `coder` PoC in `OSS lab`), `factory-burn-lab` instantiates a run-scoped `createFactory({ stateDir: "<paseoHome>/burn-lab/runs/<runId>/factory", projectSlug })` — keeping `paseo-factory`'s production `ledger.jsonl` 100% untouched.
   - Tier 1 (`Supervisor` framing) defines a real `Contract` (`gate`, `artifact`, optional `scope`) per swarm task via `factory.setContract(...)` and records `factory.spawn(...)` into an isolated git worktree (`prepareIsolatedWorktree` with `.worktreeinclude` copy + per-worktree `core.excludesFile` and `node_modules` symlink/junction).
   - Tier 2 (`Free model` execution) commits worktree changes to the attempt's branch (`burn/<runId>/<model>`) and calls `factory.claim({ task, sha, agent: model.id })`, enforcing `checkCleanAt`, `changesOutsideScope`, `MEMORY_FILES` fencing (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`), `artifact` existence, and `runGate` (`NODE_TEST_CONTEXT` stripped, process-group SIGKILL).
   - When an attempt's `Claim` or `Citation gate` fails (`verdict === "red"`) and `attempt < maxAttempts` (default `2`, configurable up to `MAX_ATTEMPTS = 3`), the `Free model` is immediately re-invoked in the same worktree with the exact `Gate` failure output or invalid citation diagnostics to self-repair at `$0` before proceeding to `Council`.

4. **Diff-Backed Cross-Family `Council` with `WATCH_QUESTIONS` and `Fresh-eyes` Semantics.**
   - For code attempts that pass `factory.claim()`, `runCouncilCrossCheck` extracts the actual git patch via `diffBetween(baseCommit, claimedCommit)` along with the `Contract`, `Gate` output, and `paseo-factory`'s five `WATCH_QUESTIONS` (`destructive-writes`, `test-weakened`, `stuck-loop`, `scope-creep`, `secret-leak`).
   - Two `Free model`s from distinct model families evaluate the real diff and `Gate` log (never trusting the worker's stdout alone) and issue `APPROVE` (`CLEAR`) or `CHALLENGE` (`CONCERN`).

5. **Smart Repo Indexer (`OSS lab`), Live UI Progress, and 1-Click `Winning branch landing` (`burn.land`).**
   - `OSS lab` indexes the inspected repository via `git ls-files`, ranks files against the prompt/subtasks, and feeds numbered excerpts across up to 10 key files (up to ~250 lines per file) so `reader-1m` models produce deep, `[path:startLine-endLine]`-verified architectural reports.
   - Launching a `Burn run` from the UI dispatches asynchronously (`awaitCompletion: false`) so `BurnLabShell`'s live polling renders real-time phase transitions (`queued` → `framing` → `swarm-running` → `verifying` → `synthesizing` → `completed`).
   - A new `burn.land` RPC and **Land Winning Branch** UI action invoke `paseo-factory`'s `landTaskWorktree` (`--ff-only` or `--no-ff` with automatic conflict abort) to merge the winning attempt's `claimedCommit` into `<project-root>` on explicit Owner approval.
